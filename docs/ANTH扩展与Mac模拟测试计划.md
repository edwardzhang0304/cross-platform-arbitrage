制定日期：2026-09-27。状态：代码与公开合约规格已核查；本文件是实施计划，尚未启动 ANTH 模拟程序，也未修改 Windows 正在运行的程序。

## 已确定的安排

- Windows 继续运行现有 OPENAI 实盘。
- Mac 用公开真实行情、虚拟资金和独立账本测试 ANTH，不加载实盘账户或密钥。
- 用户将另外创建两个账户，分别用于 ANTH 的 Lighter 和 Entropy；现在不需要它们也可以开发和模拟。
- 用户已确认：ANTH 先沿用当前 OPENAI 的开仓、加仓、平仓规则和参数做模拟。
- 最终仍交付一套 Rust 程序、一个 Windows EXE、一个本机 18794 页面，通过 OPENAI / ANTH 切换。

## 程序需要调整的六块

### 1. 从单一标的改为按标的配置

抽出统一的市场配置：两边的合约名称、市场编号、数量精度、价格精度、最低下单要求、保证金模式和计价换算关系。行情、下单、成交查询、持仓核对、手续费和资金费查询都使用同一份配置。

现有代码中的 OPENAI、io:OAI、market_id=42 不只出现在页面，也出现在成交缺失核查与账户过滤里，必须逐项消除这类隐含绑定。

### 2. 分开账户、账本与运行状态

每对标的独立保存账户绑定、凭证标识、参数、均线、网格状态、同价加仓计时、持仓组、未完成操作、成交、资金费和收益。按标的分别启动、暂停和停止，操作按钮明确显示操作对象。

保留 OPENAI 现有配置和账本的兼容性，不清零、不把原账本改成 ANTH。ANTH 创建新账本，模拟与实盘也使用不同目录；不得把模拟持仓导入实盘。两个标的的订单标识和查询过滤也必须独立。

共享一个程序并不意味着完全隔离进程故障：整个程序退出或电脑断网仍会影响所有运行中的标的。单个标的的普通查询失败应由自己的任务处理，避免误改另一对的状态。

### 3. 精确处理双腿数量和剩余成交

现有账本统一用万分之一记录数量。ANTH 的 Lighter 成交可能精确到十万分之一，不能四舍五入或丢弃尾数。

新账本按市场需要使用明确的数量尺度；旧 OPENAI 账本保持原尺度解释。正常配对组按双方共同支持的数量步长计算：本次查到的 ANTH 共同步长为 0.001，同时检查两边的最小数量、最小金额和保护价格。

举例：计划每腿 0.007，Lighter 实际只成交 0.00637，Entropy 无法直接成交同样数量。必须精确登记差额，并由原有部分成交恢复流程确定可配对数量及剩余处理方式。只有两腿核对完成，才可以把这一组标为完成；不能把 0.00037 丢掉，也不能把有余量的组标为已平仓。若最低下单要求或流动性阻止即时处理，保留待处理状态并阻止该标的继续增加风险，不能保证两个独立平台瞬间同时成交。

### 4. 规则复用，运行数据分别计算

ANTH 模拟从当前已发布版本的规则和参数建立基线，不重新解释历史讨论中的规则，也不顺便改动 OPENAI 的策略。两边合约规格与费率属于市场输入，不能复制 OAI 的市场数据。

重点核对首组门槛的 MA5m 不加 1、5 秒开仓确认、当前网格规则、同价加仓至少 15 分钟且最多 5 次、逐组平仓、持仓组数上限、0.01% 滑点限制。均线和图表使用 ANTH 自己的行情；手续费、资金费及净利润按 ANTH 自己的订单和持仓归属。

每组金额相同不代表合约数量相同。金额换算后还需按共同数量步长取整；不满足最低下单条件时明确记录原因，不偷偷放大预算或放宽滑点。

### 5. 页面增加标的切换

沿用现有图表和卡片，顶部增加 OPENAI / ANTH。各自展示价差、均线、两边账户、持仓/平仓组数、净收益、资金费和成交明细。模拟页面明显标注“ANTH 模拟”，虚拟资金不混入实盘合计。

最终 Windows 沿用 18794 入口。Mac 的本机测试入口仅指向 Mac；不会把 Windows 的 localhost 地址当作 Mac 上的服务。

### 6. 增加隔离的 Rust 模拟入口

当前正式版在服务启动处拒绝 paper 模式，虚拟成交后端只存在于测试构建中，不能直接加一个 dry-run 参数就运行。

新增测试专用入口，复用策略决策、执行状态机和账本处理，接入公开行情与虚拟成交后端。模拟构建不得具备实盘下单入口，不读取 Vault，不连接真实账户执行器。默认正式包仍不启动模拟任务。

## 实施顺序与验收

1. **建立基线与隔离目录。** 在开发分支完成改造；记录现有 OPENAI 行为，保持 Windows 原版本运行。
2. **接入 ANTH 公开行情与规格。** 完成合约单位、精度、最小量、保证金模式核对，先显示真实 bid/ask 与价差。
3. **运行 Mac 模拟。** 使用虚拟账户执行同一套策略，保存模拟开仓、加仓、平仓及每次未成交原因。模拟成交依据盘口深度、价格步长、滑点和最低金额，不能用“发出请求即全部成交”的简化方式。
4. **注入故障验证恢复。** 覆盖开仓、加仓、平仓的双边部分成交、单边拒绝、成交回报超时、重复回报、断网、重连、重启，以及五位小数尾量和最低下单限制。再运行两个模拟标的，检查操作与账本不会串用。
5. **回归现有 OPENAI。** 原策略用相同输入得到相同决策；旧格式账本可恢复；资金费、手续费、收益和数量尺度兼容。先用合成数据验证迁移，再在受控升级时核对真实账本。
6. **通过后才打新 Windows 包。** 完成 Rust 测试、签名组件测试、页面测试和不带凭证的 Windows 包测试。部署升级须安排短暂交接窗口，先停止并确认旧程序无未完成操作、备份，再核对旧持仓接续。Mac 模拟通过不等于真实账户权限和订单通道已经验证，新账户还需只读核验。

验收重点：

- 已完成组的两腿数量等量反向，且各组之和等于各自核对后的持仓。
- 未完成的双腿操作持续记账、可恢复，不因超时或重启消失。
- 重试不造成重复成交，查询只归属正确的账户与标的。
- OPENAI 原有持仓和历史收益不会因增加 ANTH 被改写。
- 模拟构建没有真实订单提交能力。

真实行情模拟可验证决策、记账和恢复逻辑，但无法证明真实撮合一定成交，也不能替代新账户权限、实际费率和保证金设置的核验。ANTH 的实盘启动不包含在本轮模拟安排中。
