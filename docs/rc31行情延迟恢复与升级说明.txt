多平台套利 Windows rc.31

本次修复
1. Entropy 持续推送但报价延迟时保留连接，继续等新鲜行情。报价停止推进超过3秒、连接断开或数据格式异常，才重新建立连接。过期报价仍不进入交易盘口，不刷新策略采样或告警的恢复时间。
2. 备用行情查询无有效结果时，等待时间依次为2、4、8、16、30秒，之后保持30秒。成功获取新的有效备用盘口后回到2秒；实时推送恢复正常后停止备用查询。查询超时和服务端限流仍生效。
3. 所有标的共用备用行情查询额度，每分钟最多120点，同时仍计入300点日常预算和900点总预算。备用查询不能借用关键订单核对的预留额度。
4. 报价卡片区分行情延迟与行情过期。诊断包增加最近接收时间、平台报价时间、延迟毫秒数、延迟次数、备用查询退避时间和额度。原先移除的监控提示区域不会恢复。

边界
程序不能让平台的迟到行情变快。报价的1500毫秒有效期、信号确认、每组7天利润目标衰减、手续费、资金费、持仓核对及保护规则保持原样。真实持续行情异常仍沿用飞书提醒。恢复连接或接收到迟到数据不会自动解除保证金、回滚、止损或人工停止保护。新鲜行情回来后，仍须满足原策略条件才能交易。

Windows 升级步骤（完整复制 data 到新包）
1. 将 ZIP 解压到桌面新的“多平台套利-rc31-Windows-x64”文件夹，先不要打开新程序。
2. 在旧后台依次点击三个账户的“停止交易”，保留后台打开。运行旧目录 Run-Diagnostics.cmd，核对各账户已停止、没有未完成订单和挂单、两边实际持仓与账本一致。已配平持仓可以保留。若有未完成订单或不配平，先保留旧后台完成核对。
3. 点击“退出所有账户”。在任务管理器确认 Cross-Platform-Arbitrage 已退出，然后备份旧程序目录。
4. 将旧程序旁边的整个 data 文件夹复制到新包 Cross-Platform-Arbitrage.exe 旁边。应为“新程序目录\data”，不要变成 data\data。保留原备份。
5. 从新目录打开 Cross-Platform-Arbitrage.exe。在 PowerShell 执行下方只读命令，应显示 0.2.0-rc.31，data_dir 指向新的 rc31 目录。
   Invoke-RestMethod 'http://127.0.0.1:18794/health' | Select-Object version,data_dir
6. 三个账户分别用原密码解锁，执行只读检查，加载原账户与账本。对照旧诊断确认持仓和账户名称一致；飞书设置随 data 迁移。
7. 观察报价卡片。若仍显示行情延迟，保留停止状态，等待平台行情恢复。行情有效且账户核对正常后，再逐个恢复原有运行模式。原有仅平仓、保证金等保护不要直接解除；需要保留保护继续管理持仓的，使用“仅恢复平仓和止损”。
8. 运行新目录的 Run-Diagnostics.cmd，将诊断 ZIP 发来核对版本、行情、持仓和通知状态。新程序产生交易后，不要用旧备份覆盖新 data。
