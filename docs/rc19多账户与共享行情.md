# rc.19 多账户与共享行情

版本 `0.2.0-rc.19`，仅交付 Windows x64 安装包。可以在同一个后台中配置两套 OPENAI 账户和一套 ANTH 账户，也可继续添加独立账户，最多 32 套。每套账户是一对独立的 Lighter RH 和 Entropy 账户。

## 账户与标的分开

- 账户管理页：`http://127.0.0.1:18794/accounts`，双击 EXE 默认打开此页。原 OPENAI / ANTH 配置、监控链接仍有效。
- 每套账户独立保存公开配置、加密交易密钥、飞书配置、订单、持仓组、费用、资金费、重试进度和控制权限。停止、启动、全部平仓、人工确认恢复仅作用于当前页面的账户。退出后台是整个程序退出，要求所有已加载账户都停止且没有未完成操作。
- 同一标的只运行一组公共行情连接和内存缓存（Lighter 一条、Entropy 一条），行情恢复机制也共享。一个账户锁定/卸载不会断掉仍在使用行情的其他账户。最后一个使用者卸载后才释放。
- 每套策略仍保留自身重启恢复需要的均线、信号和行情诊断依据，不能用公共缓存替代账本。私有账户查询按账户分别执行；不是把余额、订单或资金费合并。
- 同一个真实交易账户不能在多个槽位重复配置；重复 Lighter 账户编号、钱包或账户别名会被拒绝。当前要求每套使用独立的两平台账户，尚不支持同一交易所账户跨多个槽位共用保证金。
- 当前已接入的标的是 OPENAI、ANTH。架构支持扩展，新增其他标的仍须开发并验证交易所合约编号、精度和交易规则，不能随意填写一个币名后交易。

这次不修改进出场和配平规则：30 分钟同价加仓、每网格阶段最多 5 次、20 组上限、加仓补腿 3 秒及 0.02%～0.05% 递增、普通减仓补偿、紧急全部平仓 5%、连续回滚保护继续沿用。公共行情故障会同时影响使用该标的的账户；每套账户仍独立检查实际持仓和风险条件。

## OPENAI 账号2的资金档位

创建账号2时明确选择 **50U** 档，保存后固定在该账户，不会改变账号1或 ANTH。

| 参数 | 原账户 5U 档 | 账号2 50U 档 |
| --- | ---: | ---: |
| 每组每个平台保证金目标 | 约 5U | 约 50U |
| 逐仓杠杆 | 3 倍 | 3 倍 |
| 每组每边持仓金额目标 | 约 15U | 约 150U |
| 最多持仓组数 | 20 | 20 |
| 每个平台持仓金额上限 | 300U | 3000U |
| 两边合计累计亏损保护线 | 30U | 300U |
| 每个平台预留可用资金 | 10U | 100U |

金额按两个平台的共同数量精度向下取整，两边保持相同份额，因此实际保证金和持仓金额是近似值。50U 档一组两边合计约 100U 保证金；20 组约占每个平台 1000U 保证金，另留 100U 可用资金。价格变化、手续费和资金费都会影响实际可开组数，20 组是上限。300U 是触发保护的阈值，不保证最终损失恰好止于300U。

网格价差、均线门槛、30分钟间隔、每档5次、止盈价差及滑点百分比不放大。创建后不能用修改配置的方式放大已有持仓账户；账本与配置档位不一致会拒绝加载。省略档位字段的旧配置仍为1倍。

## Windows 升级

1. 将新版 ZIP 解压到全新的 `CPA-rc19` 文件夹，暂不打开 EXE。
2. 在旧程序停止所有账户的交易。运行旧目录 `Run-Diagnostics.cmd`，确认策略已停止、没有 pending/孤立仓位/未完成挂单，实际两边数量与各自账本一致。已有正常配对持仓可以保留。有未完成操作时先处理，不要直接退出或复制账本。
3. 点击一次“退出所有账户/退出后台程序”。只关浏览器不算退出。后台退出后，备份原程序旁完整 `data` 文件夹。
4. 将完整 `data` 复制到新程序 `Cross-Platform-Arbitrage.exe` 旁，不要形成 `data/data`。不要只复制一个数据库，也不要用模板覆盖原配置。
5. 打开新 EXE。检查版本为 `0.2.0-rc.19`、数据目录指向新目录、提交号与包内 `build-info.json` 一致：

   ```powershell
   $h = Invoke-RestMethod 'http://127.0.0.1:18794/health'
   [ordered]@{version=$h.version;commit=$h.build.source_commit;runtime=$h.build.runtime;data_dir=$h.data_dir;profiles=$h.profiles} | ConvertTo-Json -Depth 5
   ```

6. 账户管理先显示“OPENAI 账号1”和“ANTH 账号1”。它们仍是原账户，数据位置没有移动。分别解锁交易密钥和飞书，加载原账本，保持停止，核对原组数、两边数量、pending 和保护状态。行情预热及核对正常后分别启动。
7. 在账户管理点“添加独立账户”，选择 OPENAI，名称填“OPENAI 账号2”，保证金档位选择“50U · 每边持仓约150U · 亏损保护300U”，点“创建并配置”。在新页面填新两平台账户和 API 信息、保存密钥库、只读检查、加载账户、配置飞书并测试。确认新账户数据正确后再启动。**不要把账号1的 data 或账本复制给账号2，也不要在原账号1页面覆盖凭据。**
8. 运行新目录的 `Run-Diagnostics.cmd`，发送生成的 ZIP 进行验收。诊断会自动发现全部账户，分别记录账户编号/名称/标的及公共行情使用者数量。

新账户创建不会自动下单。每次重启要分别解锁、加载各账户。升级后出现新成交，不可直接用旧备份覆盖当前账本。

## 数据路径与诊断

- 原 OPENAI：`data/config`、`data/keys`、`data/runtime/openai-inventory/live.sqlite`。
- 原 ANTH：`data/profiles/anth-live`，保持原位。
- 新账户：`data/profiles/p-<固定编号>-live`；名称不参与路径，账户编号及标的建立后不能改。
- 账户目录：`data/profiles/accounts.json`，只记录编号、名称、标的，不存密钥。新旧目录及该文件一并备份迁移。
- 新账户接口：`/api/accounts/<固定编号>/inventory`、`/api/accounts/<固定编号>/control`。旧接口继续只指向原账户。
- 人工恢复脚本支持 `-Profile <固定编号>`，原 `-Market openai/anth` 兼容。仍要求本人确认、真实持仓核对、无未完成订单；不会顺便启动策略。
- 飞书异常和测试消息附加账户名称、标的与编号，用于区分两个 OPENAI。短暂恢复成功的通知抑制规则保持不变。
