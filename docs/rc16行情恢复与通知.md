# rc.16 行情恢复、诊断和人工处理通知

版本：0.2.0-rc.16。Windows 实盘与 Mac 模拟使用同一套源码；最终以 GitHub Actions 的 `verified-mac-windows` 校验结果和安装包内 `build-info.json` 为准。

## 修复内容

1. Entropy 快速行情由程序直接管理 WebSocket。连接和订阅有 4 秒期限；连续 3 秒没有有效的新盘口就销毁旧连接并重新订阅。心跳、订阅确认、其他频道消息不能冒充盘口更新；不合法的辅助标记价消息会记录错误，不再拖断正常盘口。
2. 备用 REST 补拉与重连独立工作：1.5 秒无有效推送后，约每秒尝试一次，每次最长 1.25 秒。它遵守两个标的共享的普通查询额度和平台限流冷却，不使用交易核对预留额度。恢复推送后停止补拉。
3. 补拉结果必须通过标的、价量、交易所时间检查；缓存、倒退、过期数据不能被贴上“刚收到”的新时间。原有 1.5 秒交易报价有效期保持不变。网络、平台或额度不足时仍可能暂无可用报价，程序不能凭旧价格交易。
4. API 和一键诊断新增行情来源、实时连接状态、重连次数、补拉成功/失败次数、错误时间和最近 32 条错误。诊断历史存在独立表，后台退出后也能读；不会修改仓位、成交或资金费。计数从本次加载起计算，历史错误跨重启保留。
5. Lighter 订单核对记录保留交易所状态、请求/成交数量和保护价；不再只保存笼统的“订单已核对”。这是诊断改进，不会改写既有成交或调整滑点。
6. 修复“已经配平，但仍需要人工恢复”的飞书漏报。自动配平并恢复运行的短暂异常不发；仍在修复的异常持续 60 秒后提醒；连续回滚保护等需要人工恢复的状态立即提醒，持续未处理每 5 分钟提醒一次。行情告警仍按最近 60 秒的实际不可用证据判断，恢复就撤销待发提醒。

没有变更开仓/加仓门槛、网格、同价次数、止盈、日常或重试滑点、紧急平仓和连续回滚保护。没有自动解除实盘的人工处理状态。

## 原因和可确认范围

行情推送失效时，旧恢复通道可能只靠间隔约 15 秒的补拉提供一张新盘口；这远慢于策略要求的有效期，所以页面长时间不更新、策略不能执行。旧版还丢弃了具体连接错误，不能从旧诊断倒推出最初是网络、平台关闭连接还是报文问题。新版修复恢复通道并保留具体错误。

连续回滚表示某次双腿计划没完成，已成交的部分经过补偿退出；不等于已永久留下一边持仓。达到保护次数后保持“需要处理”，必须人工检查。旧版通知代码错误地把“配平完成”和“交易恢复”当成同一件事，因此漏发这一停止状态。新版分别判断。

## Windows 升级步骤

1. 把新的 Windows ZIP 传到桌面，解压到一个全新的 `CPA-rc16` 文件夹。暂时不要打开新 EXE。
2. 在当前旧程序的 OPENAI、ANTH 配置页分别点“停止交易”。运行旧目录里的 `Run-Diagnostics.cmd`，确认两对都已停止、无 pending/孤立仓位、无挂单，账户数量与账本一致。有持仓可以升级，无需为了升级平仓；有未确认订单或数量不一致时先发送诊断，不能直接套用后续步骤。
3. 在网页点“退出后台程序”。一个后台同时管理两个标的，点一次即可。关闭网页窗口本身不算退出。
4. 退出后备份旧程序旁的**整个 `data` 文件夹**。然后把整个 `data` 复制到新文件夹中的 `Cross-Platform-Arbitrage.exe` 旁边。不要只复制 sqlite，也不要把 data 套成 data/data。完整目录包含两个标的的账户、账本、策略、加密密钥和飞书设置。
5. 只打开新目录的 `Cross-Platform-Arbitrage.exe`。在 PowerShell 复制以下命令，确认版本是 `0.2.0-rc.16`，数据目录指向刚才的新文件夹；提交号与新包的 `build-info.json` 一致。

   ```powershell
   $h = Invoke-RestMethod 'http://127.0.0.1:18794/health'
   [ordered]@{version=$h.version; commit=$h.build.source_commit; runtime=$h.build.runtime; data_dir=$h.data_dir} | ConvertTo-Json
   ```

6. 分别解锁 OPENAI、ANTH 的密钥库和飞书，做“只读检查”，加载原账户和账本，暂不启动。核对组数、两边真实数量与账本一致、没有待处理订单。让行情运行一会儿，图表应持续更新；均线需要重新积累足够有效数据。飞书可在页面各点一次测试通知。
7. 双击**新目录**的 `Run-Diagnostics.cmd`，把桌面生成的 `CPA-Diagnostics-*.zip` 发来确认。若仍显示“需要处理”，先查新的原因；不通过重装、删账本或改配置来绕过保护。
8. 核对正常后，再由本人在两个配置页分别启动实盘策略。旧目录和升级前备份先保留；新程序产生成交后，旧备份不能直接作为当前账本恢复使用。

## 后续故障怎么发资料

运行当前程序目录里的 `Run-Diagnostics.cmd`，把生成的 ZIP 发来，并附上“大约几点、哪个标的、看见什么异常”。有飞书通知就附通知时间和文字。这一包会同时读取两对的多次状态、行情错误、订单进度、账本摘要、资金费与通知状态，无需再逐段复制查询命令。

诊断不下单、不停止策略、不导出私钥或原始账本。不要把诊断包提交到公开 GitHub；其中仍含持仓和成交摘要。

## 验证要求

离线测试覆盖静默 WebSocket 的真实断开重连、备用补拉、恢复后停止补拉、REST 超时、报文/时间校验、错误脱敏和持久化，以及人工处理立即通知、自动恢复静默、持续异常提醒和去重。另以只读公共行情验证两个标的，不启动账户或策略。

交付前还必须通过 Windows PowerShell 5.1 诊断测试、Mac/Windows 的 live/paper 单元测试与签名参考向量、前端测试、Windows 安装包无凭据启动检查，以及两系统两模式的决策轨迹一致性校验。测试通过不等于 Windows 的真实网络或账户已现场恢复，仍以升级后新诊断为准。
