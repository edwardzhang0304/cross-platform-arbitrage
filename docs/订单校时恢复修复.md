# 0.2.0-rc.4 订单校时恢复

2026-09-28 的故障证据显示 Windows 时间约快 95 秒，两对均有第一腿实际成交、账本仍记为零的未决操作。修复不修改策略参数、账户配置或历史请求时间。

- Lighter 先核对账户、市场、客户端订单号、交易所订单号、方向、原始数量、限价和只减仓标志；成交还必须关联同一个交易所订单号。
- Entropy 先核对 cloid、市场、方向、原始数量、限价和只减仓标志，再从交易所订单创建时间查询成交。
- 共享执行核心接受核实后的交易所创建时间作为成交校验起点，保留原始成交时间、数量、费用和去重标识。创建时间差超过 5 分钟仍拒绝自动接受。
- 新下单前核对近期交易所时间，时间缺失、偏差或证据过期时拒绝签名。只读历史订单查询继续可用。
- ANTH 的 Lighter 下单使用市场规定的 5 位数量精度；OPENAI 保持 4 位。
- 只读状态增加 `view.order_lookup_note`，保存最近一次超时订单查询详情，避免被后续账户差额提示覆盖。

增加的合成回归覆盖：95 秒时钟偏差、OPENAI 490 单位平仓、ANTH 700 单位开仓、原始请求不重复提交、SQLite 重启后去重、错误账户/市场/订单/数量/价格/时间拒绝，以及两边仓位必须等量反向且等于剩余组数量。CI 必须通过 Mac/Windows 的 live/paper 测试、签名向量、前端测试、Windows 无凭证启动检查和共享核心比对。

交接时先退出旧后台并备份整个 data，再替换经过验证的程序。保留原有配置、密钥库、账本及未决操作，不能清空 pending 或手工伪造成交。加载账户可能继续处理原有未决双腿操作；后续需要核对真实仓位、挂单、pending 和账本。代码及合成测试通过不等于真实账户已经恢复。
