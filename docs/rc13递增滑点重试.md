# rc.13：配平失败后的递增滑点重试

普通首腿、普通对冲腿仍使用原配置 0.01%。已经发生一边成交、另一边未配平时，保护性补偿首次使用 0.02%，确认该次失败或部分成交仍有剩余量后依次使用 0.03%、0.04%、0.05%，以后保持 0.05%。每张新单以当时该平台最优买卖价计算允许范围，实际成交按真实价格记账，并非固定扣除该百分比。

- 原有失败后的冷却从 5 / 15 / 30 秒改为固定 3 秒。确认失败后的下一次机会会重新核对盘口和认证持仓。交易所响应时间、限流、断网或无有效行情仍可能延长实际间隔。
- 未配平的开仓、加仓，沿用只减掉多出来一边的回退规则；平仓则继续减掉另一边的对应剩余数量。精度对齐与非公共精度尾数回退也使用同一阶梯。不会扩大原计划数量，不重新开回已平的一边。
- 价格范围内连一个最小数量步长也买卖不到时，记录本档失败、持久化档位及下次时间，3 秒后使用下一档。盘口预检查不会发单，也不为明显不满足价格条件的重试反复消耗账户查询额度。过期或无效盘口不会推动档位。
- Entropy 补偿可分次处理当前保护范围内可成交的剩余数量，不要求一次吃完整笔。下一片必须先确认上一单终态。
- 不明订单保持原编号、原价格及原数量，只查询，不能当成失败重发。超时后的后台查询机会也改为 3 秒，沿用统一 API 限流。确认终态后才能增加滑点及发出下一张剩余量订单。
- 阶梯、当前等待原因和下一次尝试时间进入原账本。新程序读取旧账本时，已提交的不明订单继续查原单；只有确认终态后的新补偿从 0.02% 开始，不根据旧重试次数直接跳到上限。
- 到 0.05% 仍未完成，保留异常状态、继续受保护处理剩余仓位，并按既有飞书规则持续异常 60 秒后提醒。不会宣称已经配平，也不会继续新增开仓。
- 手动“平掉全部持仓（紧急止损 · 5%）”继续走独立的 5% 紧急通道。普通收益止盈条件、5U 网格、30 分钟同价加仓和每档 5 次额度不变。

同一个 Rust 核心同时用于 Windows 实盘和 Mac 模拟，两标的规则一致。只读状态 API 增加 recovery_policy；诊断包增加 recovery_slippage_bps 与 recovery_wait_reason，便于判断卡在第几档及原因。不包含私钥。

## Windows 升级

1. 将新包解压到单独的 rc13 文件夹，避免和旧程序合并。
2. 两标的停止交易，确认没有未完成订单、孤立仓位，且账本和两平台持仓一致。存在未完成操作时先保留诊断包处理，不能把它当成普通迁移直接删除。
3. 退出旧后台，完整备份原 data 文件夹。把原 data 完整复制到新 EXE 旁，保留配置、加密密钥、账本和飞书设置。
4. 启动新 EXE，先用 /health 确认版本 0.2.0-rc.13、提交号及新数据目录。分别解锁和加载两标的，再检查实际持仓和账本，最后恢复策略。
5. 运行新包的诊断 CMD，确认两标的 recovery_policy：retry_interval_ms=3000、initial_slippage_bps=2、step_slippage_bps=1、max_slippage_bps=5、unknown_order_action=lookup_only。确认正常后再清理旧安装包，保留本次升级备份直到确认完成。

本地不启动模拟盘或实盘；升级包不会自动替换 Windows 上正在运行的版本。
