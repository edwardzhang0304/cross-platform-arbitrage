# rc.11：恢复查询不再等待普通查询额度

rc.10 的账户并行查询仍共用原来的 300 权重/分钟限额。一次完整 REST 账户快照需要 44 权重；两个标的每 15 秒回退一次就需要 352 权重，尚未计入下单前重复检查、查单和账户模式查询。耗尽后内部等待最多跨越一分钟，而交易工作线程在 3–10 秒截止，外层只显示通用超时。此路径可在合成 HTTP 服务复现；旧现场日志未记录限流阶段，不能认定每次现场超时都由它引起。

## 修复范围

- 普通查询仍最多使用 300 权重/分钟；为账户强制核对和原订单查证预留额外 600。总额 900，低于官方 1200 权重/IP/分钟，仍保留外部调用余量。成交/资金费等返回行数的额外权重也计入；服务器 429 与冷却仍生效。[官方限流说明](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/rate-limits-and-user-limits)
- 交易查询额度不足或服务器冷却时立即返回明确原因；HTTP 单次等待最多 2.5 秒，不在短执行窗口内隐藏六次重试。重试仍由原有持久化恢复流程安排。
- HTTP 查询共享连接池。下单可消费一次同一账户刚完成的 REST 证据，必须仍在原来的 3 秒有效期内；按开始采样时间计龄，不重新盖时间戳。失败查询、不同账户、未来时间、过期证据和仅有流式快照都不能充当该证据。提交前消耗缓存，查单时清除缓存，保留原有仓位、reduce-only、保证金、时钟和订单期限校验。
- 诊断包增加不含账户标识的额度状态；错误保留具体请求类型和原因。

不调整入场、网格、加仓间隔、滑点、止损或持仓归属。继续保留取消全部平仓后的停止状态；只处理已有未完成操作。结果未知时只查原订单，不按仓位差猜测成交，也不生成重复下单。

## 验证与现场边界

合成测试覆盖两标的同时核对和查单、普通额度耗尽、总额度耗尽、429 冷却、网络超时、作用域取消、额外响应权重、一次性账户证据及原风险门槛。运行原有残余分批恢复、未知订单与重启恢复回归；构建以 Windows/Mac 两模式、签名、Windows 无凭据启动及跨平台相同核心验收为准。

本机与 CI 均不连接真实交易账户。测试通过不能代替升级后的现场验收：应加载原账本并保持停止，重新收集诊断，确认新鲜账户与账本一致、pending 清除及取消全平标志仍有效。
