rc.23：逐仓保证金核对与加仓拒单保护（仅 Windows x64）

这次解决什么
平台显示的“可用余额”可能包含当前仓位的估值空间，不能直接当成新订单可以划入的逐仓保证金。已有逐仓里的保证金和浮盈也不会自动变成账户外面的现金。此前程序按前者放行，可能出现第一边已成交，Lighter 却因 margin-not-allowed 拒绝，再把第一边撤回；放大滑点无法解决这种资金不足。

新版在第一边下单前及 Lighter 实际发送前核对原始 collateral、available_balance、现有逐仓权益和保证金率，按订单价格计入不利成交差、手续费及原有安全预留。缺失证据或不支持的混合全仓风险不允许新增开仓，不影响原有减仓恢复。

若平台仍返回已确认结束的保证金/余额拒单，立即终止加仓的滑点重试，按确认成交记录只撤回本次未配平部分。已有配对仓位保留。新增开仓保护写入账本，重启、普通启动和自动冷却均不能解除。双腿已配平但仍被保护暂停时会发飞书提醒；恢复过程的短暂异常仍沿用原有通知等待规则。

普通价格未成交仍按既有 3 秒、0.02%～0.05% 的加仓补腿规则；未知订单仍只查原单，不能直接当成没成交重下。正常平仓、止损和紧急全平不套用新增开仓的现金要求。不会自动充值、划转保证金、改杠杆或改策略额度。

监控“可用于加仓”显示保守可划转金额，鼠标提示保留平台显示可用额及未划入逐仓余额。该值还没有扣除新订单成本及安全预留，不等于可以全部下单。一键诊断新增原始金额、保证金率和拒单保护记录，不导出密钥或账户地址。

升级：把完整 data 复制到新版本目录
1. 把新 ZIP 传到 Windows 桌面，解压为单独的“多平台套利-rc23-Windows-x64”文件夹，先不要打开新版 EXE。
2. 在旧后台三个账户分别点击“停止交易”，保留后台打开，等到全部已停止。运行旧程序目录中的 Run-Diagnostics.cmd，确认没有未完成订单、挂单或孤立仓位，两边实际数量与各自账本一致。有已配平持仓可以升级；如仍在配平或数量不符，先发送诊断包，不要退出迁移。
3. 点击“退出所有账户”，然后确认 Windows 任务管理器中 Cross-Platform-Arbitrage 进程已消失。关闭浏览器页面不等于退出后台。
4. 将旧程序文件夹完整复制一份作为升级前备份。当前版本可能为 rc22、文件夹名字却仍是 rc21，以 /health 的 data_dir 和实际程序所在目录为准。
5. 从刚退出的旧程序目录复制整个 data 文件夹，粘贴到新 rc23 包中 Cross-Platform-Arbitrage.exe 的同一层。结果为“新目录\Cross-Platform-Arbitrage-Windows-x64\data”。不要只复制某个数据库、不要形成 data\data、不要合并两份不同时间的账本。新包原本不带 data；如误启动生成了 data，先退出并保留该目录，重新解压一份再迁移。
6. 只打开新目录的 Cross-Platform-Arbitrage.exe 一次。保留旧目录作为备份，不要再启动旧 EXE。在新程序文件夹地址栏输入 powershell 回车，再执行下面整段核对：

$ErrorActionPreference='Stop'
$h=Invoke-RestMethod 'http://127.0.0.1:18794/health' -TimeoutSec 10
$expected=Get-Content -LiteralPath '.\build-info.json' -Raw | ConvertFrom-Json
$expectedData=[IO.Path]::GetFullPath((Join-Path (Get-Location).Path 'data')).TrimEnd('\')
$actual=[string]$h.data_dir
if ($actual.StartsWith('\\?\')) { $actual=$actual.Substring(4) }
if ($h.version -ne '0.2.0-rc.23' -or $h.build.runtime -ne 'live' -or $h.build.dirty -or $h.build.source_commit -ne $expected.source_commit -or $h.build.strategy_core_sha256 -ne $expected.strategy_core_sha256 -or $actual.TrimEnd('\') -ine $expectedData) { throw '版本或数据路径不符，先不要启动策略，把 health 输出发来' }
[ordered]@{version=$h.version;commit=$h.build.source_commit;data_dir=$h.data_dir;result='VERSION_OK'} | ConvertTo-Json

7. 三个账户用原密码解锁、运行只读检查并加载原账本，暂不启动策略。核对原账户、原持仓和飞书配置都在。运行新目录 Run-Diagnostics.cmd，把新 ZIP 发来做一次升级验收。诊断会自动收集三个账户，不需逐段输入查询。
8. 验收持仓配平、没有 pending 后再分别启动。若出现“保证金拒单保护”，先处理实际可划转保证金不足，再停止该账户并点击“核对并解除开仓保护”。按钮会重新读取两平台持仓、订单与资金，条件不满足则拒绝解除；解除成功仍保持停止，需单独启动。不要反复点恢复或手改账本。原有连续三次回滚保护也仍需人工核对。
9. 保留旧版升级前备份直到新版本验收通过。新版产生交易后，不能把旧备份账本覆盖回来。

边界
本修复消除已识别的资金口径错误和确定保证金拒单后的自动反复加仓。平台状态可能在查询和下单之间变化，网络、盘口或其他平台规则也可能拒单，不能保证双腿永不出现短暂不一致；终态核对、只按已确认成交减仓、异常保护与通知仍保留。
