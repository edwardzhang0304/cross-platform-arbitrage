# rc.9 升级说明

本次更新统一两个标的的监控布局，移除监控页面的挂单列，改为持续交易异常 60 秒才通知，并附带一键只读诊断。网格 5U、同价加仓间隔 30 分钟、每网格阶段最多 5 次及所有成交、配平、账本规则保持不变。挂单仍是后台风控与诊断必查项。

## 正常运行的 rc.8 如何升级

1. 新 ZIP 解压到一个新目录；不要覆盖当前运行目录。保留新目录里的三个诊断工具文件。
2. 在当前后台的 OPENAI 和 ANTH 配置页分别停止交易。可以先把新包的 `Run-Diagnostics.cmd`、`Read-Diagnostics.ps1`、`DiagnosticsSqlite.cs` 三个文件复制到旧 EXE 旁，双击 CMD 生成升级前诊断包。
3. 确认两个标的停止，真实账户与账本一致，没有 pending、孤立仓位或挂单，再正常退出后台。若检查不通过，发送诊断包，先处理未完成操作。
4. 后台退出后备份整个旧程序目录，把旧目录完整的 `data` 文件夹复制到新 EXE 旁。不要用包内配置模板覆盖实际配置。
5. 打开新 EXE。解锁并加载两个标的；飞书配置也需解锁。暂不启动交易。双击新目录 `Run-Diagnostics.cmd`，核对实际版本 `0.2.0-rc.9`、运行路径/数据目录、持仓账本、未完成订单、参数、通知启用状态。账户检查通过后再启动两个标的。
6. 启动后再生成一次诊断包，确认 `running`、真实数量与账本一致及通知启用。旧备份先保留，完成验收后再清理；升级后的真实成交不能用旧备份覆盖回去。

两个标的共用一个后台，因此退出一次会同时关闭两个页面的后台服务；浏览器页面本身可能仍留着。

目录名称不用必须带 rc9。以 `/health` 返回的实际版本和提交、进程路径为准。一键诊断也会收集这些字段。

## 以后发生异常

保持后台打开，双击 `Run-Diagnostics.cmd`，把桌面生成的 `CPA-Diagnostics-*.zip` 发来，附一句现象和最近是否手动交易/重启/改过网络。完整说明见同目录的《故障排查与处理流程.md》。

脚本通常半分钟左右完成，只读取本机接口、脱敏账本事件、时间与磁盘状态。不会自动上传，不需要提供私钥、整个 data 或逐条执行修复命令。
