# rc.15：行情告警按实际观察计时

rc.14 把“第一次行情过期后经过多久”当作“行情异常持续多久”，要求连续健康 10 秒才清除。如果反复短暂过期，或交易线程被账户查询拖慢，可能在行情已更新时仍发送“持续异常 60 秒”。rc.15 用独立采样和明确证据替换这个计时，不改变交易策略、持仓或订单恢复。

## 提醒规则

- 每秒独立检查两边最新盘口；账户查询和飞书网络请求不会拖住这个检查。原交易报价有效期仍为 1.5 秒。
- 按每个平台分别统计最近 60 秒。观察满 60 秒、其中至少 48 秒（80%）不可用，并且发送前该平台仍不可用，才提醒。完全断流 60 秒会提醒；仅偶尔补取一帧、绝大部分时间无法使用，也会提醒。
- 一分钟里偶尔卡几秒不满足上述门槛。两平台各自短暂卡顿不会加在一起计算。
- 文案写“最近 60 秒约有 X 秒盘口不可用”，不再把间歇故障说成完全没有更新。
- 报价恢复或异常占比降到门槛以下，立即撤销待发通知。获取飞书令牌后、发消息前，再读取一次最新盘口。已发给飞书的请求无法撤回，恰好与恢复同时发生时仍可能收到一条发送时有效的消息。
- 每个标的成功发送后至少间隔 5 分钟再提醒。失败按原飞书投递退避重试，断网不无限堆积同类消息。
- 观察间隔超过 3 秒、时钟倒退或重新加载账户时，重新收集行情证据；空白时段不能当成行情一直异常。旧版未发出的行情提醒会清理，交易异常提醒不受影响。
- 交易异常的 60 秒等待、已有订单核对、数量精度、重试滑点、止损和紧急平仓规则保持原样。Windows 实盘与 Mac 模拟引用同一份 Rust 核心。

## 诊断

继续运行程序目录的 `Run-Diagnostics.cmd`。rc.15 新增每个标的的 `market_alerts`：当前采样证据、已观察时长、每个平台不可用时长、最新盘口时间、固定原因类别，以及最近 64 条排队/发送/取消记录。记录只涉及通知，不写交易事件、持仓或资金账本；固定条数避免长期运行占满磁盘。诊断仍按字段白名单导出，不包含密钥、账户地址或通知凭据。

## 回归范围

使用合成行情验证连续断流、少量卡顿、每隔 15 秒恢复一帧、两个平台交替短暂异常、48 秒门槛、观察停顿、时钟倒退、重启、旧通知迁移、五分钟去重、发送前恢复、独立采样、诊断脱敏及历史记录上限。测试不连接真实账户，不下单，不发送真实飞书消息。发布前还须通过双方运行模式、签名测试、前端、Windows 无凭据启动检查及 Mac/Windows 核心一致性检查。

## Windows 升级

1. 新 ZIP 解压到独立的 rc15 目录，不与旧目录合并。
2. OPENAI 和 ANTH 分别停止交易，保持后台打开，运行旧版一键诊断。确认两边均停止、无 pending/孤立仓位，真实数量与账本一致。持仓可以保留，不需要为了升级平仓。
3. 点击一次“退出后台程序”，确认后台进程退出。备份完整旧 `data`，然后把完整 `data` 复制到新版 EXE 旁。
4. 启动新 EXE，核对 `/health` 为 `0.2.0-rc.15`，提交号与交付说明一致，数据目录指向刚复制的新目录。
5. 分别解锁、加载两个标的，检查实际账户、账本、持仓组数与飞书已启用。保留原账户绑定、配置、持仓、历史和加密凭据，不重新新建账户或账本。
6. 核对正常后分别启动两个策略。运行新版 `Run-Diagnostics.cmd`，发送诊断包验收。

遇到 pending、数量不一致或进程未退出时，保留现场发送诊断，不用旧备份覆盖正在运行的账本。新版发生真实成交后，旧备份已不能直接作为当前账本使用。打包不会自动升级或停止 Windows 程序。
