# rc.17 人工确认解除连续回滚保护

版本：0.2.0-rc.17。本次仅交付 Windows x64 实盘包。Windows 上的 live/paper 共用核心回归和决策轨迹仍需一致，不生成 Mac 安装包。

## 解决什么问题

之前连续三次回滚后，仓位即使已经配平，也没有人工确认解除保护的入口。重启和点击启动都不会解除这项保护。现在两个标的的配置页共用一个“核对并解除连续回滚保护”按钮，在连续回滚次数达到 3 时显示。

操作前先点击本标的“停止交易”，等状态显示“已停止”。按钮要求本人确认，后台随后强制重新查询两个平台，不用页面缓存充当核对结果。

必须同时满足：

- 策略已停止，且确实触发了连续回滚保护。
- 没有未完成的开仓、加仓、平仓或配平订单。
- 两个平台的实际持仓分别与账本一致，且与持仓分组总量一致；双腿数量相等、方向相反。已全部平仓时允许双方都是零。
- 两个平台都没有挂单；证据经过认证，属于当前绑定账户，未过期、未来自未来时间，逐仓和杠杆设置正确。
- 没有孤立仓位、亏损保护或尚未结束的全部平仓任务。

查询失败、超时、任一项不满足或账本写入失败，均不解除保护。完整账户查询最多等待 20 秒；队列中的前序工作可能增加页面等待时间。

成功后仅清除连续回滚次数和相应恢复等待、旧信号确认，保留持仓、成交、网格锚点、加仓次数、费用、收益和其他保护。核对证据和人工确认作为同一事务写入本地账本；重复发送同一个操作编号不会解除后来的新异常。不会发订单，也不会自动启动；仍须本人另点“启动实盘策略”，启动时再次执行原有风险检查。连续三次回滚保护以后仍会重新生效。

## Windows 升级步骤

1. 把新 ZIP 解压到全新的 `CPA-rc17` 文件夹，暂不打开 EXE。
2. 在旧程序里分别停止 OPENAI、ANTH。运行旧目录的 `Run-Diagnostics.cmd`，核对两对均已停止，没有未完成订单或孤立仓位、无挂单、两边持仓与账本一致。有持仓可以升级。若仍有未完成订单或数量不符，先发诊断，不能跳过这一步。
3. 点击一次“退出后台程序”，两个标的会共用同一个后台退出。关闭网页不等于退出后台。
4. 退出后，备份旧程序旁的整个 `data` 文件夹，再把整个 `data` 复制到新 EXE 旁。不要只复制数据库，不要套成 `data/data`，不要用空白模板替换原账户配置。
5. 只打开新目录里的 EXE。在 PowerShell 执行：

   ```powershell
   $h = Invoke-RestMethod 'http://127.0.0.1:18794/health'
   [ordered]@{version=$h.version;commit=$h.build.source_commit;runtime=$h.build.runtime;data_dir=$h.data_dir} | ConvertTo-Json
   ```

   版本必须为 `0.2.0-rc.17`，数据目录应指向新目录，提交号应与新包的 `build-info.json` 相同。

6. 分别解锁两个标的和飞书通知，做只读检查，加载原账户和原账本。先保持停止；若加载后暂时显示“正在核对恢复”，等它核对结束。
7. 在触发保护的标的页面（本次为 OPENAI），点击“核对并解除连续回滚保护”，阅读弹窗并确认。成功后应显示“连续回滚次数为 0”，恢复按钮消失，策略仍为“已停止”。没有触发保护的 ANTH 不需要这一步。任何失败都按错误提示处理并发诊断，不能手改账本。
8. 等行情、账户核对和均价预热正常后，由本人分别点“启动实盘策略”。运行新目录里的 `Run-Diagnostics.cmd`，把生成的 ZIP 发来验收。旧目录和升级前完整备份暂时保留；一旦新版产生新成交，不能直接把旧备份当作当前账本使用。

## 也可以用 PowerShell 人工恢复

必须先完成升级、解锁、加载和停止。打开新 EXE 所在文件夹，在空白处右键打开 PowerShell，运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Confirm-Rollback-Recovery.ps1 -Market openai
```

脚本会要求输入 `OPENAI` 并回车确认。ANTH 对应 `-Market anth`，确认时输入 `ANTH`。脚本与网页调用同一个后台检查，不会自动启动实盘，不会读取或导出私钥。成功输出 `VERIFIED` 后，仍需在网页另点启动。

如果请求超时或输出不明确，先刷新状态或运行诊断，确认操作结果；不要自行改数据库。该命令不适用于 rc.16 及更早版本。

## 验证与范围

合成测试覆盖两个标的、停止与启动分离、持仓和账本不一致、同向仓位、挂单、待处理订单、过期/未来/未认证/错账户证据、亏损与紧急平仓保护、网络失败和超时、写盘失败、重启持久化，以及重复请求不会释放后来的保护。另验证前端确认与取消、分标的令牌/确认文本、Windows 包装与无凭据启动、PowerShell 诊断。

本次不修改开仓/加仓/平仓门槛、止盈、滑点、自动重试、连续回滚触发次数或飞书告警策略。人工解除并不保证后续订单必成交，异常仍执行原配平、回滚与通知机制。
