# rc.12：手动紧急全部平仓

原按钮只设置正常策略的 close_requested，已有 pending、配平故障或盘口保护可以使它一直排队。现在手动 close_all 会持久化独立的紧急退出状态，在普通策略、原配平、资金费查询之前处理。

- 操作范围是当前页面标的在已绑定的两个专用账户中的实际持仓；OPENAI 和 ANTH 分别点击。立即禁止新开仓、加仓，全部完成后保持停止。
- 每个平台独立读取认证持仓和新鲜报价，以只减仓 IOC 处理实际剩余数量。相对提交时该平台最优买卖价，最大滑点为 5%（500 bps），不是固定收费。一次部分成交，确认该订单终态并重新查询实际持仓后继续处理剩余量；没有整笔盘口深度、均线、价差、盈利、资金费齐全或网格条件限制。
- 普通策略的滑点不变。平台断网、没有 5% 内的对手盘、认证失效或实际存在未结束挂单时不能保证即时归零；界面明确保留剩余数量及原因。不得突破滑点上限、捏造行情/账户、修改保证金模式或发出增加仓位的反向单。
- 原配对订单仍然保留并查询，但不等待原配平成功才减仓。所有新请求都只减仓；新紧急订单结果未知时，只查询同一编号，不重复发送。原开仓迟到成交时继续减掉新出现的剩余持仓。旧请求未确认终态前，不宣告完成。
- 每个意图提交前写入 SQLite，重启后继续查询原请求。独立保存待核对成交，全部原请求终态与新鲜账户零持仓一致后，按真实成交记账并结束旧持仓归属。账户数量差不能生成虚构成交或盈亏。不完整历史会显示持仓已归零但账本待核对，保留原账本。
- 两平台任务独立推进，一侧查询失败不会阻止另一侧减仓。两端控制台与监控页显示进度，删除“取消全部平仓请求”按钮及公开操作入口。紧急退出期间不允许重新启动；停止新增交易不会撤销退出。
- 飞书继续沿用延迟告警：紧急退出长期未完成才通知；完成后取消该事件尚未发送的通知。
- “平仓净收益”字段名称保持不变；它仍是已平仓部分的累计净收益，新增亏损平仓会降低该数值。紧急平仓有真实成交分配记录，不能把原卡住订单的成交重复计入。

共享 Rust 模块 emergency_exit.rs 同时用于 Mac 模拟与 Windows 实盘，纳入核心哈希和模式隔离检查。合成回归覆盖两个标的、两个方向、原开仓/加仓/平仓挂起、回执丢失、旧订单迟到、部分成交、重启、单侧查询失败、错误账户、过期证据、5% 边界、只减仓以及已平收益归属。测试不连接真实账户。

升级仍须先检查现场状态和备份原 data；本功能不会远程修改正在运行的旧 Windows 程序。发布必须通过 Windows/Mac 两模式、签名测试、前端、PowerShell 诊断脱敏及 Windows 无凭据启动验收。
