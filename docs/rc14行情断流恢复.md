# rc.14：行情断流自动恢复

OPENAI 和 ANTH 各自连接交易所，同一台电脑上的一个标的正常，不代表另一个标的正常。“报价过期”指程序收到的盘口太旧，不是合约到期，也不是 API 私钥到期。

原来的 Entropy 连接超时检查被任何消息刷新。盘口停止更新时，标记价格、成交推送或其他消息仍可能继续到达，使连接一直显示正常。独立 REST 补取只能间歇填补报价，不能替代持续盘口。诊断可以确认盘口长时间未更新及恢复机制缺口，不能仅凭快照确定最初断流是服务端还是网络造成。

## 修复行为

- OPENAI 和 ANTH 共用同一实现，分别检查各自的 Entropy 快速盘口订阅。有效盘口连续 3 秒未到达就结束旧连接，按现有重连节流重新订阅；其他消息和 REST 补取不会重置这个计时。普通低频订阅保留原行为。
- 清理旧 WebSocket 的读取和心跳任务，防止断流重连不断遗留连接及占用内存。
- 保留原有 1.5 秒报价有效期：超过这个时间就不能作为常规下单依据。3 秒是重连触发门槛，不是放宽交易价格有效期。
- 页面在每个平台的买卖价下显示“行情有效”“报价过期”或断连等状态，悬停可看最近盘口时间。最新价差缺失时明确提示暂停更新，不补画虚假价格。
- 策略运行、持有仓位或有未完成订单时，持续行情异常 60 秒后通过已有飞书配置提醒；同一异常最多每 5 分钟一次。连续有效观察 10 秒才视为恢复，短暂 REST 更新不会掩盖持续故障。恢复取消未发提醒，短暂异常保持静默。行情提醒和交易异常提醒独立。
- 不改变开仓、加仓、平仓规则、数量精度、现有订单恢复、滑点及账本内容。Windows 实盘和 Mac 模拟使用同一份 Rust 策略核心。

恢复连接不意味着马上交易。均线仍需足够的有效行情，满 20 组也仍受原持仓上限限制。

## 升级

1. 新包解压到单独目录。两个标的停止交易，运行一键诊断确认无未完成订单，且账本与真实持仓一致。
2. 退出旧后台，备份完整旧 data，然后将 data 完整复制到新 EXE 旁。保留已有持仓、配置、加密密钥及飞书设置。
3. 启动新版，检查 `/health` 版本为 `0.2.0-rc.14`、提交号符合交付说明，数据目录为新目录。
4. 分别解锁加载两标的，核对账户与账本；观察两平台报价持续有效，再恢复策略。
5. 再运行 `Run-Diagnostics.cmd`，发送诊断 ZIP 验收。存在未知订单时保留现场，走故障处理流程，不用旧备份覆盖当前账本。

本地测试不启动模拟盘或实盘。打包不会自动更新 Windows 正在运行的程序。
