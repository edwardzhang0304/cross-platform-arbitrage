# Mac / Windows 共用同一策略核心

唯一源码仓库是 `openai-paired-trader`。两个程序都编译 `src/strategies/openai_inventory/` 下同一份 Rust 核心，不手工同步两份策略。OPENAI 和 ANTH 也调用这份核心，各自持有配置、账户绑定和账本。

## 规则当前状态

- 首组门槛 `max(MA5m, 5)`，不加 1；开仓确认 5 秒。
- 网格步长 5U，按本轮首组实际开仓价差形成网格。
- 同价加仓距最近一次完成开仓/加仓至少 1 小时，每个网格阶段最多 5 次。
- 网格双腿实际成交、数量配平并完成记账后，同价次数重新从 0 计算；未用次数不累加。零成交、未确认成交、尚有单边差额均不能重置。
- 总持仓最多 20 组。平仓继续使用逐组 `max(实际开仓价差×50%, 2)` 的目标缩小幅度；本次不加入 24 小时衰减。
- 缺少 `accumulation.quota_scope` 的旧账本保持旧的整轮额度，防止只换程序就悄悄改变正在运行的实盘。新模板明确为 `grid_stage`。

## 哪些相同，哪些可以不同

| 部分 | 要求 |
| --- | --- |
| MA、开仓/加仓/平仓条件、额度计数 | 同一份代码，相同参数和输入得到相同决策 |
| 精度配平、部分成交恢复、账本、净收益公式 | 同一份代码；按标的规格处理数量 |
| 资金费证据新鲜度 | 两种模式共同要求最新同步证据；模拟盘不再跳过 |
| 订单和资金费来源 | 实盘读取平台真实成交和结算；模拟使用虚拟成交及公开历史资金费估算 |
| 强平证据 | 实盘核对平台真实持仓消失；模拟使用明确的强平近似生成虚拟成交，均交由配平恢复流程处理 |
| 密钥、账户绑定、数据目录、启动授权 | 按实盘/模拟隔离，模拟程序不具备实盘下单适配器 |
| EXE、Mac 启动文件、防休眠、浏览器打开方式 | 操作系统适配 |

共用代码不等于两边实际收益必然一样。行情到达时间、实际成交价、资金费结算证据与模拟近似仍有差异。

## 怎么判断安装的版本是否一致

新版页面底部显示程序版本、核心编号、参数编号；包内 `build-info.json` 记录完整核心摘要和源码提交。也可运行 `--build-info`，该命令立即退出，不启动后台、不创建账本。

同一标的两端的核心编号与参数编号都应一致。账户地址和实盘/模拟标识不计入参数编号；不同标的规格会影响编号。旧版没有编号时不能认定已对齐，需要安排升级。

GitHub 工作流在 Mac 和 Windows 上分别测试 live/paper 四种组合，对同一批 96 帧合成场景核对决策摘要，覆盖两个标的、两个方向、开仓/网格/同价/平仓、资金费缺失或过期、断线、旧盘口、资金不足及紧急退出。另运行完整回归测试，包括部分成交与重启恢复。只有四份结果、源码摘要和两个包内编号相同，才产生 `verified-mac-windows` 安装包。

Mac 本机保持停机，不为测试重新创建模拟历史或编译缓存。当前 Windows 已安装旧包不会被远程改动，升级与旧账本配置转换需要单独交接。
